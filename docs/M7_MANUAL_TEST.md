# M7 存档、设置与恢复人工验收

本轮只在全部代码完成后启动一次程序。开发期间不要运行 `npm run dev`，否则文件监听器会在每次保存源码时自动重启 Electron 窗口。

## 1. 启动与自动保存

1. 执行 `npm run dev`。
2. 切换到布置模式，移动一个食盆，新增一段栅栏，再旋转一个设施。
3. 等待至少 3 秒。
4. 从托盘选择“退出 DeskHabitat”，不要直接结束 Node/Electron 进程。
5. 再次执行 `npm run dev`。

通过标准：设施位置、方向、容量、栅栏、兔子位置及需求值均恢复；退出时不会长期卡住。

## 2. 设置独立性

1. 在托盘“目标显示器”中选择一个显示器（只有一台时保持当前选择）。
2. 切换“置于普通窗口上方”的选项。
3. 从托盘正常退出并重新启动。

通过标准：显示器与窗口层级设置恢复；调试窗口无论该设置为何都不会保持最上层。设置保存在 Electron `userData/settings.json`，世界存档位于 `userData/saves/`，两者互不嵌套。

## 3. 主存档与备份恢复

先完成至少两次保存，确保 `habitat.json` 与 `habitat.backup.json` 都已生成。退出程序后再修改文件。

1. 备份 `userData/saves/` 目录以便测试后恢复。
2. 将 `habitat.json` 内容改为 `{broken`，保留备份文件不变。
3. 启动程序。

通过标准：程序从 `habitat.backup.json` 恢复，不白屏、不崩溃；控制台给出备份恢复警告。随后正常保存会生成新的有效主存档，同时不会用损坏的主存档覆盖可读备份。

## 4. 双重损坏回退

1. 退出程序。
2. 将主存档和备份都改成无效 JSON。
3. 启动程序。

通过标准：程序加载默认栖息地并可正常操作，控制台提示没有可读存档。

## 5. 离线结算与存档内容

1. 正常退出，等待一小段时间后重新启动。
2. 观察饥饿、口渴和精力变化。
3. 用文本编辑器检查 `habitat.json`。

通过标准：离线需求变化有上下界，最多只结算 8 小时；JSON 含版本、应用版本、保存时间、世界、兔子、设施、栅栏和游戏时间，不含 PixiJS 对象、函数、选中对象、拖动状态或工具栏状态。

## 6. 回归检查

- 生活、布置、暂停模式仍可切换。
- 栅栏连续拖动及轻微停留延迟正常。
- 移动、旋转、删除设施后兔子会重新规划。
- 透明桌面模式的置顶策略不影响普通调试窗口。
- 关闭测试程序后，PowerShell 中按 `Ctrl+C` 停止 `npm run dev`，避免后续编辑触发窗口重启。
