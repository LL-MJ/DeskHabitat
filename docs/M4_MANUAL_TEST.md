# M4 导航与栅栏人工验收

## 初始场景

1. 运行 `npm run dev`。
2. 确认草地上显示一组 L 形木栅栏，栅栏相邻部分视觉上连续。
3. 在生活模式观察兔子，确认黄色调试路径只经过相邻的上下左右格。
4. 等待兔子移动到栅栏另一侧，确认它沿路径绕过栅栏，没有穿越阻挡格。
5. 确认左上角显示导航网格版本和重新寻路次数。

## 动态栅栏

1. 从托盘切换到“布置模式”。
2. 在空草地格按下左键并保持，拖过多个相邻格后松开，确认只在本次拖动经过的栅栏柱之间生成横杆。
3. 分别绘制横向、纵向、对角和连续转弯笔画，确认整个过程无需松开鼠标或锁定单一方向。
4. 指针进入新格后确认出现候选提示；短暂停留后才生成连接，快速擦过相邻格不会落下栅栏。
5. 保持按下并依次经过多个方向，最后回到起点，确认可以一次连续拖动闭合围栏。
6. 单击一个空格，确认只放置独立栅栏柱，不与周围栅栏自动连接。
7. 单击已有栅栏柱，确认该柱及与它直接相连的横杆被删除。
8. 尝试从兔子当前所在格开始绘制，确认不会在兔子脚下新增栅栏。
9. 在黄色路径的后续格绘制栅栏，再切回生活模式。
10. 确认导航版本增加，兔子放弃旧路径并绕开新栅栏或安全返回待机。

## 稳定性

1. 保持生活模式运行至少 10 分钟，并多次进入布置模式增删栅栏。
2. 确认兔子始终位于可通行格，没有穿越栅栏、越界或长期卡住。
3. 确认终端和开发者工具没有未处理异常。

## 通过标准

- A* 能处理可达、不可达、绕路和起终点相同情况。
- 兔子仅沿四方向路径移动，不穿过阻挡格。
- 栅栏变化会使旧路径失效并触发安全重规划。
- 横杆只来自用户的连续拖动笔画，相邻栅栏不会自动连接。
- 无有效路径或当前位置失效时，兔子能安全恢复而不持续卡死。
